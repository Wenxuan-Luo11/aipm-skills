# 阶段交接与上下文预算

是否交接、是否换会话由用户决定。阶段结束本身不触发强制交接或重开聊天；快速原型、同一薄片和连续小修默认继续。出现上下文增长明显、反复遗忘/重读、长时间中断或任务大幅转向时，可用一句话说明建议及代价，用户选择继续就继续，不机械追问。用户要求交接或已授权换会话时，再执行下述流程。短交接建议约 600–1000 字，更长证据留文件链接，不压缩成含糊的“都完成了”。用户喊停时立即收尾，不以完善体系为由扩展。

清屏只是界面动作，不保证模型历史被移除。使用宿主实际支持的新会话/上下文机制；无法调用时写交接并说明下一入口，不冒称已经清空。交接同时保留总目标与当前薄片，避免下一会话把上传等子任务误认为整项交付。

交接只保留：目标与人类已确认决定；工作区/分支/未提交变更；已完成事实和证据路径；失败与未验证项；下一闭环及停止条件；必要授权/隐私约束。标明生成时点。不要复制完整历史、日志、源码或失败输出。

获授权的新会话先核对 git 状态和交接指向的当前文件，只读取本阶段必需 Skill 与入口；对旧结果按版本核实，不重跑无关调研。发现交接不足，定点取证，不把完整旧聊天重新注入。仅要求写交接不等于授权创建新对话；用户未要求切换时，不因写了交接就自动结束当前任务。

另设四条日常预算：工具返回截取必要行；原始日志留文件只回报摘要；同一问题不重复全库搜索；独立子任务返回结论、文件和证据，不返回完整思维/工具轨迹。阶段内按需委托，避免让所有子 Agent 继承完整历史。

启动子代理前说明独立产物、允许范围、验收与上下文入口；只有隔离或并行收益超过派单/验收成本才用，宿主和用户授权优先。独立读取可批处理，依赖操作按顺序；同一输入/版本的成功证据复用，变化后才重验相关范围。重复同因失败先诊断，避免无界重试与轮询。经验先留案例，能机械判定的约束移进脚本，删除重复提示；不为省 token 删除必要证据。

参考：[OpenAI Skills](https://learn.chatgpt.com/docs/build-skills) 的元数据→正文→资源加载；[Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) 的即时检索、压缩、结构化笔记与独立上下文。这里采用文件/路径检索，不要求向量库，也不宣称已实现 API 工具历史清除。

成本审计区分累计输入、缓存输入、非缓存输入、输出、工具轮次、模型请求与观察、测试时间、人工等待。累计输入不是唯一上下文长度，也不是账单。换会话会丢缓存并产生重新加载成本，交接遗漏还可能返工；节省幅度通过同类任务实测，不承诺固定百分比。

## 执行时的五条预算

- **按版本复用证据**：记录输入内容指纹、命令、运行环境及结果。匹配且成功才复用；输入变动或缺失则重验相关范围。CI/发布门禁强制新跑。`scripts/check.py` 是本包实例，项目里优先复用自己的检查入口；本地记录可信，不是防伪证明。
- **摘要与批处理**：独立只读操作一次批处理；结果只返回状态、计数、证据路径和必要错误片段。全日志落文件，失败后定点读取；依赖和写入操作顺序执行，不盲目并行。
- **先诊断再重试**：默认不自动重跑失败测试。同因失败先查退出码/错误与输入；只有条件变化或确认瞬时故障才重试。同一外部操作最多补试两次，再报告具体阻塞，不把重试当修复。
- **CI 去重**：feature 走 PR 检查，main push 验证合入结果，保留手动触发；同分支新提交取消旧运行。必要的跨平台矩阵保留，不能通过跳过测试节省时间。
- **机械规则**：清单、资源引用、许可证、哈希、范围等由脚本检查；产品价值、体验反馈与证据是否足够仍由人/模型判断。新增检查后删除重复长叮嘱，以脚本为事实源。

方法参考：固定版本 Addy 的 context-engineering、planning-and-task-breakdown，以及 Oil 的持久任务契约和独立委托。交接保留为按需能力，由用户决定是否采用；不声称上游要求每阶段自动新开聊天。
