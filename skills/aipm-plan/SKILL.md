# 分级计划与执行

先核对项目规则、工作区状态、真实路径、可复用能力和检查入口；已有证据直接使用，未知才定点查。方案围绕可观察变化、范围与复用、风险边界、验收四件事。

## 选择最轻流程

| 级别 | 何时用 | 怎么做 |
| --- | --- | --- |
| L0 | 简单解释、定义、状态答复 | 已有上下文直接短答，无必要不调工具、不改文件 |
| L1 | 范围清楚的小改动或已知原因缺陷 | 简述改法→修改→相关快测；缺陷先复现 |
| L2 | 常规功能、中等调整或少量产品取舍 | 给简短方案；关键取舍由用户确认，已有授权不重问 |
| L3 | 跨系统、高风险或重大接口/数据变化 | 按项目风格落盘规格、核查失败恢复与兼容，确认后分批执行 |

审阅已有方案只核对事实、复用、范围和遗漏，不顺手实现。执行中发现新增风险、范围或产品分歧，更新方案再继续。

## 执行与完成

- 不因 L2/L3 自动派单；只在独立产物、隔离或审查收益值得时委托。高风险方案按需独立只读挑刺；小修不叠加审查仪式。
- 实现前明确目标、工作区、允许改动、复用项、检查和停止条件。保护用户改动，多写任务隔离；执行者不自行扩大范围或操作远程。
- 按用户可观察结果验收，包括可见反馈、结束与下一步；引擎/接口成功不足以证明体验完成。只报实际运行的检查，不放宽测试。
- 实现后核对 diff 范围、检查结果和未验证项；重要改动进入可用的独立审查。发布/合并前新跑必要门禁，按仓库及用户授权执行，不直接 push main。
- 简报阶段、验收进度、证据及阻塞。交接和换会话由用户决定，不自动停工。

## 仅在需要时读取

- 写 L2/L3 方案、任务契约、查偏好、隔离或收尾：读 [方案与执行细则](references/plan-rubric.md) 的对应章节。
- 用户选择子代理模式：读 [分工约定](references/subagent-mode.md)；真实 CLI 委托再加载可用的 aipm-delegate。
- 用户要求交接、或需要诊断上下文/执行成本：读 [上下文与预算](references/context-handoff.md)。

原因不明的缺陷转 aipm-bug-fix；实际代码审查转 aipm-code-review。这些入口不可用时保留任务边界并说明限制，不假称已完成独立检查。来源与许可见本目录 SOURCE-NOTICE.md。
