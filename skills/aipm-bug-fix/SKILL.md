# 先复现，再修根因

先核对项目规则、相关检查和用户改动。问题与修法已明确时直接小修，不强走完整诊断；范围、接口或风险变化时再对齐。

## 最短闭环

1. **复现**：优先加会失败的回归测试并确认失败；不适合自动化时保留可重复步骤。线上/偶发问题复现不了，就记录日志依据和未证实假设，不冒称找到根因。
2. **定位**：诊断期间只加必要复现与临时日志，不混入产品改造。沿错误值、好坏版本或正常对照定位第一次产生错误的地方；因果链要能解释当前现象和边界。
3. **定范围**：区分个例与相同根因的普遍问题，定点搜索确认。跨模块、高风险、接口/数据变化或超出授权时，先说明修法和影响，不顺手全库改。
4. **最小修复**：在错误产生处修。不能用特判、吞异常、无依据重试/sleep或增大超时掩盖根因；不删除、跳过、放宽失败测试。
5. **验证**：同一复现用例修前失败、修后通过，再做关联快测；删临时日志，说明未验证的运行环境。个例通常保留回归即可，不追加通用规则。

## 何时停止

两轮修复仍失败、连续假设被推翻或证据互相矛盾时，暂停猜测，汇总已知事实、排除项与复现入口。有收益且获授权时再请求独立只读诊断，不默认启动固定数量/型号的子代理；仍无解就报告阻塞或提出可选简化。

## 汇报与参考

短报根因/位置、修复、修前修后检查和限制；查过历史才报告引入提交。普遍问题列处理范围，新增自动检查或常驻规则先核对已有授权，不反复求批也不自行扩展。

只有需要二分历史、追值、对照、偶发排查或止损细节时读 [根因方法](references/root-cause-methods.md)。代码审查、跨模块规划、治理分别使用可用的 aipm-code-review、aipm-plan、aipm-govern；无需为完成小修加载所有入口。来源与许可见本目录 SOURCE-NOTICE.md。
