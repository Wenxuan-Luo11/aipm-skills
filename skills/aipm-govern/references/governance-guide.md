# 按模式治理：命令与细则

仅阅读当前模式章节，不因治理任务把所有参考文件加载。`SKILL_DIR` 指本 Skill 的绝对目录；执行已有采集脚本：

```text
python <SKILL_DIR>/scripts/audit_repo.py --workspace <项目路径> --scope <docs|tests|board|worktrees|all> --json
```

按问题选 scope，all 仅用于明确要求的全仓体检。board 的 --fetch 需要网络与既有授权，否则标明远程可能过期；大JSON留文件并提取相关字段。脚本本身只采事实。

## 文档治理

AGENTS 仅保留必要入口和全局边界；字节数作诊断信号，不是凑数指标。删除重复与过期叮嘱，命令/模板下沉到有明确触发条件的 reference；不要只拆文件后仍要求全部阅读。其他宿主入口按其实际支持引用同一事实源，不盲写不支持的 @ 语法。保留来源与许可。项目专属开发约定需要时读 dev-profile.md。

## 测试治理

先看 CI 实际运行命令和项目定义入口，再判断孤儿或慢测试。局部改动运行相关快测；同输入/版本的成功证据可复用，CI/发布门禁新跑。识别空断言、过量mock、长sleep及真实配置/外部服务副作用；删除测试要有“不再覆盖有效行为”的证据和任务授权，不能以瘦身代替质量。

feature 优先只走 PR CI，main push 验证合入结果，保留手动触发；同分支新提交取消旧任务，必要平台矩阵保留。检查成功、配置存在、required checks生效分别报告，不能混为一谈。

## 工作树治理

先核对工作区改动、提交保存位置及实际合入方式；merged/squash_merged/rebase_merged 且无未提交改动才是候选。no_own_commits、远端已删除或是主干祖先，均不能单独证明可删。工作树放主仓库外，避免重复扫描。

列出准确目录、分支、证据和清理后果；只对用户已批准清单执行，不自动删未合入工作。需要图示/分支建议再读 branch-board.md；单纯文档治理无需读看板与工作树细节。
