# 匿名案例：把实现完成变成用户可观察的完成

以下经验来自一个交互原型的开发过程。案例省略产品名称、行业、部署地址、客户、代码标识和具体功能细节，仅保留可复用的方法；不是用户研究或商业效果证明。

| 观察到的问题 | 转成的约束 | 入口 |
| --- | --- | --- |
| 内部状态已结束，但界面没有给出清楚的完成反馈 | 验证可见完成、结果说明和下一步，而不只看状态/接口 | delivery-check |
| 已有明确方向仍做不影响决定的比较 | 实验必须能改变当前取舍，否则缩小或停止 | product-discovery、aipm-plan |
| 创建部署后就宣称用户可用 | 分开核查构建、部署、访问与完整旅程 | delivery-check |
| 用事件次数推断人数与因果 | 明确主体、顺序、窗口、去重和证据边界 | telemetry-audit |
| 长轮次没有清楚的状态反馈 | 简报当前阶段、验收证据、下一项及等待来源 | AGENTS.md |
| 为每件小事派单导致协调成本过高 | 小任务直达，有隔离或独立产物收益才委托 | aipm-plan、aipm-delegate |

限制：本例未公开原产品、源码、原始日志或用户数据；不能由案例推断乐趣、留存、商业价值或普遍提速。匿名历史审计见 cost-audit.md，不能当作完整最终账单。
