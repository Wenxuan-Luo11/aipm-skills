# 最小评估：先看行为，再谈效率

固定三类问题：虚假上线/分析声明、界面缺少可见完成反馈、少量事件的错误漏斗推断。每类同一素材、相同型号与权限；baseline 不附 Skill，treatment 附相关 Skill。每个会话独立，记录是否识别缺证据和具体下一步，不以回答篇幅评分。

这只是小型行为探针，单次样本不能建立统计结论，模型本身可能已经做对。记录总输入输出 token（包括上下文与工具）、实际型号、工具轮次、耗时、检查成功和人工修正。请求的型号不自动算已观察型号。没有完整 token 元数据就报告缺失，不用账户配额百分比反推。

禁止为漂亮结果挑掉失败样本；质量相同时才比较成本。跨项目至少再纳入小修、独立实现和发布任务，积累分位数后才给滚动耗时范围。

本轮具体结果见 `../docs/validation.md`。后续升级 Skill 时复跑相同素材，并加入真实失败回归；不要把对照回答直接拿来训练本次评分。
